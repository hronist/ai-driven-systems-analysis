# Приложение к Модулю 1: Альтернативные нотации

Необязательный материал. В [Модуле 1](./01-system-boundaries.md) для фиксации границ системы используется C4 — этого достаточно для большинства задач разработчика. Ниже — альтернативы, которые могут потребовать в отдельных компаниях или контекстах. Как и C4, это языки записи уже принятого решения, а не методы анализа.

## UML (Unified Modeling Language)
Классический стандарт. Для границ системы используют **UML Use Case Diagram** (прямоугольник границ системы, внутри — функции, снаружи — актёры) или **Component Diagram**. Понимается во всём мире, часто обязателен в финтехе и аутсорсе.

* [UML Use Case Diagrams — справочник](https://www.uml-diagrams.org/use-case-diagrams.html)

## DFD Level 0 (Data Flow Diagram)
В отличие от C4, которая показывает зависимости, DFD показывает *потоки данных*. Система в центре, стрелки — какие конкретно данные (например, JSON с профилем) летят внутрь и наружу. Удобно для проектирования DTO.

## ArchiMate (в связке с TOGAF)
Тяжёлая артиллерия для Enterprise Architecture. Позволяет на одной схеме связать бизнес-процесс, конкретный API и физический сервер в дата-центре. Актуально в основном для крупных enterprise-компаний с выделенной ролью архитектора.

Если ваша компания не требует конкретно эти нотации — можно пропустить и вернуться к [Модулю 1](./01-system-boundaries.md).
