# Модуль 2: Выявление требований и Бизнес-процессы

Требования не лежат на поверхности. Их нужно "выкапывать" из стейкхолдеров и текущих процессов.

## 1. Психология заказчика и "The Mom Test"
Заказчики приходят с **решениями** ("Сделайте кнопку выгрузки в Excel"), а не с **проблемами** ("Мне нужно сводить данные для налоговой").
*   **Правило Mom Test:** Спрашивай о прошлом, а не о будущем. Не спрашивай "Вам нужна эта фича?". Спрашивай "Как вы решали эту проблему на прошлой неделе?".
*   Слушай больше, чем говоришь. Ищи "боли", за которые бизнес готов платить.

Mom Test — это техника для шага **Discovery / Research** из жизненного цикла идеи (см. Модуль 1, п.1): именно на этом этапе вы проверяете, что проблема реальна, а не выдумана.

### Mom Test — не единственный инструмент
Интервью работает с тем, что люди *говорят*. Дополняйте его источниками, которые показывают, что люди реально *делают* (подробнее — Модуль 1, п.2):
*   **Анализ существующих данных** — тикеты поддержки, аналитика, логи ошибок.
*   **Наблюдение (shadowing)** — посмотреть на реальный процесс, а не только выслушать его описание.
*   **Совместные воркшопы** — свести нескольких стейкхолдеров вместе, чтобы противоречия в их версиях процесса всплыли сразу, а не по частям в отдельных интервью.

## 2. Моделирование процессов: BPMN 2.0
BPMN (Business Process Model and Notation) — мировой стандарт описания бизнес-процессов. Если ты не понимаешь процесс, твой код автоматизирует хаос.
*   **AS-IS (Как есть):** Как бизнес работает сейчас (часто это пересылка Excel-файлов в Telegram).
*   **TO-BE (Как будет):** Как процесс будет работать после внедрения твоей системы.

**Базовые элементы BPMN:**
*   **Pools / Lanes (Пулы и Дорожки):** Кто выполняет работу (например, дорожка "Студент", дорожка "Python Backend", дорожка "Менеджер").
*   **Tasks (Задачи):** Действия (User Task - делает человек, Service Task - делает скрипт).
*   **Gateways (Шлюзы):** Ветвления (Эксклюзивный "ИЛИ", Параллельный "И").

### Альтернативные нотации процессов
BPMN — стандарт де-факто. В отдельных компаниях можно встретить UML Activity Diagram, EPC или IDEF0 — см. [Приложение: Альтернативные нотации процессов](./02a-alternative-process-notations.md), если конкретно ваша компания их требует.

## 🛠 Практическое задание
**Задача:** Процесс "Возврат средств за курс".
1.  **Интервью:** Составь 5 вопросов по методологии Mom Test к менеджеру поддержки, чтобы понять, как они делают возвраты сейчас (AS-IS).
2.  **BPMN TO-BE:** Опиши текстом (или нарисуй в PlantUML/Mermaid) процесс возврата в новой системе. 
    *   *Участники (Дорожки):* Студент, TS Frontend, Python Backend, Платежный шлюз.
    *   *Условие (Gateway):* Если пройдено больше 10% курса — отказ в возврате. Иначе — автоматический возврат.
